paint/garden.planes, run at an arbitrary day. The whole picture is a pure function of two inputs — the day (tick) and the seed below — never of state carried across ticks: this program declares no state.json surface at all. Drag the scrubber anywhere in the cycle, or change the seed, and the page re-runs the program from scratch at exactly the values shown — never an interpolation toward them.

This is a sibling of paint.html, not a mode of it: a single fixed program, no picker, no play loop — the day scrubber replaces both, since a pure function needs no loop to explore.

Serving: this page fetches paint/garden.planes and imports js/*.mjs as ES modules — both are refused from a file:// origin. Serve the repo root (python3 -m http.server 8000) and open http://localhost:8000/garden.html. No bundler, no transpiler, no network dependency beyond that server: everything loads from this same directory.

Purity. The picture at a given (day, seed) pair is always the same picture — scrub away and back, or retype a seed you used before, and the page redraws exactly what it drew the first time, because every run starts from state: nothing and reads nothing else. Saving. SVG and PNG capture the day shown right now, not a fresh run — the same "what's on screen" rule paint.html's exporters follow.

After an update. The .planes fetch carries a per-visit token and is never served stale. The .mjs module graph cannot: if a browser ever serves a mix of old and new modules, the output pane says so and names the fix — in Safari, Develop → Empty Caches, because a plain reload keeps ES modules.
